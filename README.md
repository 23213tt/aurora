# Aurora

一个 Windows 桌面音乐播放器，做各音乐平台的客户端。登录你自己的账号，听你有权听的音乐；本机已有的文件也可以是其中一个来源。

界面不带固定配色——进度条、导航高亮、舞台的极光带，颜色都来自当前播放的那张专辑封面。

---

## 用起来是什么样

**打开就在唱。** 正在播的那一句歌词放大在画面正中，上下几行按距离排开、逐渐变淡，背后是随音乐起伏的极光带和粒子。想看歌词不需要点开任何面板。

**封面决定颜色。** 换一首歌，整个窗口的色调跟着封面走。没有播放时界面是灰的，不抢眼。

**左侧列出来源，底部是播放栏。** 每个音乐平台是一个入口，本地文件也是一个，点一下就切过去。歌单、搜索、每日推荐都在各自的来源里。

---

## 音乐从哪来

软件本身不带音乐。它做的是**连到你已有的账号或文件**，这一点必须先说清楚：

| 来源 | 你需要有什么 | 状态 |
| --- | --- | --- |
| **网易云音乐** | 一个网易云账号（不登录也能搜索和播放一部分） | 能用 |
| **本机文件** | 电脑上有音乐文件，或者你自己整理的文件夹 | 能用 |
| QQ 音乐 | 一个 QQ 音乐账号（不登录只能听免费歌，见下） | 能用 |
| Spotify、Apple Music、自有音乐服务器（Navidrome / Jellyfin 等） | — | 还没做，接入方式（官方 OAuth / 密码）已在代码里标好 |

**为什么只有这些。** 音乐是有版权的，任何播放器都拿不到曲库本身——参考的那些播放器也都是在做「连到你已有的东西」。所以这里能做的只有两件事：接平台（用你自己的账号和权限），或者读你自己的文件。除此之外的第三条路（绕过平台的付费与授权）不做。

## 怎么开始用

### 安装

去 [Releases](https://github.com/LN334/aurora/releases) 下载最新的 `Aurora-<版本>-Setup.exe`。

安装时 Windows 会拦一次——这个安装包没有购买代码签名证书。点「更多信息」→「仍要运行」就能继续。所有未签名的软件都这样，不是程序有问题。

### 听网易云

左侧「在线音乐」→「搜索在线音乐」，直接搜就能听，**不需要登录**。

登录之后（同一位置，或搜索页的登录按钮）会多出你的每日推荐、我喜欢的音乐、云盘和歌单。登录的是**你自己的网易云账号**——能听的只有你这个账号本来就有权限听的歌。

网易云不是官方接入，详见 [关于网易云](#关于网易云)。

### 听本机的音乐

首次启动会自己去找你电脑里的音乐文件夹（一般是用户目录下的「音乐」）。找到了就开始扫描，歌曲出现在左侧「本地音乐」里。

找错了位置，或者想换一个：左侧「音源」→ 添加或移除文件夹。移除之后它不会自作主张加回来。

### 怎么登录

两个平台都是**用手机 App 扫码**，不需要在这里输入密码：

| 平台 | 入口 |
| --- | --- |
| 网易云音乐 | 左侧「网易云音乐」这一段的「登录」，或页面上「登录网易云音乐」链接 |
| QQ 音乐 | 左侧「QQ 音乐」这一段的「登录」 |

扫码后登录凭据会加密存在本机（用 Windows 自带的加密），不会上传，也不会写进日志。

**QQ 音乐尤其建议登录**：未登录时实测只有约 18% 的歌能播，流行的歌几乎全都要登录。

登录是按「档案」分开的——一个档案一个账号，切换档案就是换账号。左侧底部「我」里管理档案。

### 多个账号

左侧底部「我」里可以建多个档案，比如「我」和「客厅」。每个档案有自己的网易云账号和自己的播放列表，切换档案就是换一套。

## 主要功能

### 在线平台

- 搜索平台曲库并播放，**不登录也能搜索和播放**
- 登录自己的账号后：每日推荐、我喜欢的音乐、我的云盘、我的歌单
- 音质档位可选（标准 / 较高 / 极高 / 无损），上游给不了某一档时会说明并回退
- 播不了的时候告诉你**具体原因**：没登录 / 需要会员 / 地区限制 / 只有试听片段 / 已下架 / 请求太频繁 / 网络问题

### 本机曲库

- 扫描文件夹建索引，读标签、内嵌封面、同目录的 `.lrc` 歌词
- 增量重扫：只重读改动过的文件
- 专辑封面墙、歌曲列表、艺术家、文件夹树、专辑详情（按唱片原序）
- 支持 mp3、flac、m4a、mp4、aac、ogg、oga、opus、wav、wv、ape、aif、aiff、wma

### 播放

- 十段均衡器，5 组预设，双击推子归零
- 淡入淡出与交叉淡化
- ReplayGain 音量标准化（峰值限幅，不会削波）
- 随机播放、列表循环、单曲循环
- 队列面板：按实际播放顺序显示，可点击跳转、可移除
- 想「下一首播放」某首歌：右键它，或用列表右侧的 ⋯ 菜单

### 歌词

- 支持 `.lrc`：多时间戳、`offset` 偏移、逐字标记、GBK 与 UTF-8 自动识别
- 沉浸歌词舞台：极光带与粒子随音乐起伏
- **桌面歌词**：独立的透明置顶窗口，默认鼠标穿透，永远不会挡住你点下面的东西。解锁后可拖动、可调字号
- 在线歌词：本机找不到歌词时可以联网查（默认关闭，开启前会说明会发送什么）

### 搜索

一个搜索页，顶部标签切换来源（目前是「网易云音乐」和「本机曲库」）。本机来源边打边出结果，在线来源按回车搜索，两边都在同一个列表里显示。

### 播放列表

- 新建、重命名、删除
- 拖拽排序，也支持 `Alt+方向键`
- 导入导出 m3u / m3u8（导入时会告诉你有多少条在曲库里找不到）

### 桌面集成

- 系统托盘：关窗口不退出，音乐继续播。真正退出走托盘右键菜单
- 任务栏缩略图按钮：上一首 / 播放暂停 / 下一首
- Windows 媒体控制（音量键旁边那个面板）、硬件媒体键

### 键盘快捷键

| 按键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `方向键左右` | 快退 / 快进 5 秒 |
| `Ctrl + 方向键左右` | 上一首 / 下一首 |
| `方向键上下` | 音量增减 |
| `L` | 打开 / 关闭歌词舞台 |
| `E` | 打开 / 关闭均衡器 |
| `Ctrl + K` | 跳到搜索框 |
| `Esc` | 关闭当前打开的面板 |
| `Ctrl + Alt + L` | 显示 / 隐藏桌面歌词 |
| `Ctrl + Alt + K` | 锁定 / 解锁桌面歌词（解锁后才能拖动） |

### 设置

左侧「偏好设置」里可以改更新频率、在线歌词开关、网易云音质、交叉淡化时长、均衡器、桌面歌词字号，以及查看和清空缓存（不会删曲库和设置）。

## 关于两个在线平台

**两个都不是官方接入，都没有得到任何授权。**

网易云走的是社区逆向接口（[NeteaseCloudMusicApiEnhanced](https://github.com/neteasecloudmusicapienhanced/api-enhanced)），QQ 音乐走的是另一个社区逆向实现（[qq-music-api](https://github.com/Rain120/qq-music-api)）。这意味着，对两者都成立：

- **仅供个人学习自用**。这类接口属于未授权访问，也违反服务条款。
- **随时可能失效**。平台一改就可能坏；被风控识别后账号可能有风险。
- **不能绕过付费**。不破解加密音频、不破解会员音质、不解锁付费专辑。能播的只有你账号本来就有权限播的。
- **不下载、不转存**。只是在你的账号范围内播放，不把音频留下来。

权限不够时界面会给出具体原因，不会笼统说一句「播不了」。

### 不登录时两个平台差别很大

这一点值得单独说，因为它直接影响你点下去有没有反应：

| | 网易云 | QQ 音乐 |
| --- | --- | --- |
| 搜索 | 可以 | 可以 |
| 免费歌曲 | **完整播放** | **完整播放**（128k） |
| 需要会员的歌 | 给试听片段 | **拿不到，点了没反应** |
| 实测可播比例（未登录） | 免费曲可整首、付费曲有试听 | **293 首取样里只有 18.4%** |

QQ 音乐的数字是实测的：流行的歌几乎全是付费曲（`payplay === 1`），未登录一律返回 `result=104003`。所以**用 QQ 音乐建议先登录**，否则多数歌曲点下去只会看到一句原因说明。

### 官方通道的情况

两个平台的官方开放接口都不面向个人桌面软件。QQ 音乐的开发者平台文档原文是「**暂不支持个人开发者申请接入**」，接入终端只列了移动应用 / 网站小程序 / 智能硬件 / 车载应用 / 公播盒子，没有 PC 桌面；条款还要求独立专区、品牌露出、上报听歌流水。网易云的开放平台同样只面向合作方。所以逆向接口是目前唯一的实现路径，风险由使用者自行判断。

## 你的数据

**默认状态下，Aurora 不联网做任何和音乐相关的事。** 下面几处需要联网，每一处都要你主动开启或触发。

### 你的音乐文件

全部在本机，索引存在本地，不上传任何东西。

### 网易云账号

- **登录凭据加密后只存本机**。用 Windows 自带的加密（DPAPI）保护，明文不落盘、不进日志。别人拿到你电脑上的文件也解不开。
- **每个档案一份凭据**。切换档案就是切换账号。
- **退出登录就清掉了**。
- **但该发给网易云的还是会发**：搜索关键词、你播的歌、账号 cookie 最终都会送到网易云的服务器。上面说的是 Aurora 自己怎么存，不是「用了就不联网」。

### 在线歌词（默认关闭）

歌词优先读音频旁边的 `.lrc` 文件——那是你自己的文件，永远优先。

本机没有时，可以去 [lrclib.net](https://lrclib.net) 查（开源、公开 API、不需要账号）。这个开关默认关闭，打开前会明确告诉你会把**歌曲标题和艺术家**发送出去。查到的歌词缓存在本机，第二次播放就不用再查，离线也能看。

### 更新检查

读 GitHub 的公开接口，不上报使用数据。可以改成「手动」。

## 常见问题

**装的时候被拦了？**
安装包没有代码签名。点「更多信息」→「仍要运行」。

**不登录能听吗？**
能。网易云的搜索和播放不需要登录，登录只是把你的歌单、每日推荐、云盘和红心带进来。

**某首歌提示播不了？**
界面会说是哪种原因（需要会员 / 地区限制 / 只有试听片段 / 已下架等）。这是平台的权限判断，软件不会绕过它。

**扫描不到我的音乐？**
左侧「音源」里手动添加文件夹。如果加进去了但没找到歌，界面会**把正在扫描的路径列出来**，这样你能看出是路径选错了，还是那个文件夹里确实没有音乐文件。

**点关闭按钮怎么没退出？**
这是刻意的——关窗口只是收进托盘，音乐继续播。真正退出走托盘右键菜单里的「退出 Aurora」。

**换了网易云账号，歌单没变？**
在左侧底部「我」里切换档案。每个档案有自己的账号。

请先了解这些再决定是否使用：

| 事项 | 实际情况 |

<details>
<summary><b>加一个平台要做什么</b></summary>

音源接缝是 `src/features/library/source.ts` 里的 `TrackSource`，成员只有六个：

```ts
id / name / summary / online / streamUrl(track) / artUrl(track) / lyrics(track)
```

播放内核不假设「歌就是磁盘上的文件」——「这首歌的音频、封面、歌词从哪来」全部经过这个接口。现在实现了两个：`localSource` 与 `neteaseSource`。

两个硬约束：

1. **`artUrl` 必须同源或带 CORS 头**，否则封面进不了 Canvas 取色。
2. **音频要经主进程代理**（`aurora-remote:`），因为渲染层的 CSP 只放行自己的私有协议。代理顺带做 Range 转发与地址白名单（拒绝指向本机和内网的地址）。

账号侧的位置也已经留好：`src/features/accounts/providers.ts` 里的 `ProviderId` 包含 `subsonic`、`lastfm`、`listenbrainz`、`spotify`、`apple`，每条都写明了它需要什么（密码 / token / OAuth）以及当前状态。**状态不是 `ready` 的平台不会出现在界面上**——设置页不是路线图。

</details>

<details>
<summary><b>技术栈与代码结构</b></summary>

Electron 44 · React 19 · TypeScript 5.9 · Vite 7 · Zustand 5 · music-metadata 11

无 UI 组件库，无图标库（图标是手写的内联 SVG），无 CSS 框架。

```
src/app/          外壳：App、路由、预览开关、侧栏、标题栏、跨功能 hook
src/features/     功能模块：accounts / library / lyrics / netease / player / playlists / settings
src/views/        页面与面板
src/ui/           共享基元：卡片、封面、图标、列表、时间格式化
src/stage/        歌词舞台与可视化
electron/pure/    零 Electron 依赖、可在裸 Node 下测试的纯逻辑
electron/protocols/  三个私有协议
```

依赖方向单向：`views → features → ui`，`electron/pure` 不依赖其它 `electron` 模块（否则无法在测试里加载）。

界面规则：一页只有一个标题（外壳打印）；本地与在线共用同一套卡片；不在页内造侧栏；颜色只来自封面（判断配色看 `src/styles/tokens.css`，不看截图）。

完整记录见 [`docs/ui-design.md`](docs/ui-design.md) 与 [`docs/architecture.md`](docs/architecture.md)。

</details>

<details>
<summary><b>性能测量结果</b></summary>

单核百分比。Windows 任务管理器显示的是全机占用，除以逻辑核心数即可。

| 场景 | 单核忙时 | DOM 变更/秒 |
| --- | --- | --- |
| 空白页对照 | 0.72% | 0 |
| **空闲（暂停）** | **0.73%** | **0** |
| 前台播放，无舞台 | 2.05% | 17.5 |
| 前台播放 + 舞台 | 5.74% | 28.6 |
| 窗口隐藏 | 0.16% | 1.7 |

大曲库（5000 首）：55,209 个 DOM 节点、JS 堆 29 MB、滚动帧间隔 p95 17 ms、超过 33 ms 的帧 0 个。**不需要虚拟化。**

主进程启动链 37.9 ms、常驻 1.04 MB。网易云上游包首次加载 1492 ms / 29 MB，但为懒加载，启动不付。

判定规则：同产物连跑抖动约 ±0.3pp，差异小于 0.5pp 不要声称是优化；跨会话数字不可直接比较。口径与对照方法见 [`docs/perf-baseline.md`](docs/perf-baseline.md)。

</details>

<details>
<summary><b>测试覆盖与已知缺陷</b></summary>

247 个用例只覆盖不依赖 Electron 的纯逻辑：LRC 解析、m3u 编解码、队列推进、文件夹树、版本比较、档案隔离、协议路径校验、扫描节流、网易云相关纯函数、搜索来源的记忆。

这组测试抓到过两个真缺陷：按文件夹播放会连带播放同前缀兄弟目录（`C:\Music` 匹配到 `C:\Music2`）；把 IPv4 伪装成 IPv6 的 SSRF 绕过。

三个审计脚本（已接入 `npm run check`）：

```bash
node scripts/audit-reachability.mjs   # 从真实入口走 import 图，找无法加载的文件
node scripts/audit-css.mjs            # 找代码与 HTML 都合成不出来的 CSS 类
node scripts/audit-stale-paths.mjs    # 找指向已不存在文件的路径引用
```

第三个是重构后加的：搬文件之后测量脚本里的旧路径会静默失效——工具找不到模块只记一行 FAILED 就继续，数字从报告里消失而没人注意到。它抓到过一次。

</details>

<details>
<summary><b>已知限制</b></summary>

- 软件没有在真实 Electron 窗口里端到端跑过（开发沙箱无法启动 Chromium）。界面用浏览器渲染加无头截图验证，主进程代码通过类型检查并成功打包，但「双击安装、扫码播放」这条完整路径未经实机验证。
- 平台只有网易云，且依赖第三方逆向接口，随时可能失效。
- 曲库索引和在线数据是两套：平台的歌不进本地曲库，也不参与档案隔离，由在线视图自己持有。
- 档案只隔离播放列表和网易云账号；曲库、播放偏好、均衡器是设备级的。
- 在线歌词只接了 lrclib.net 一个源。
- 大曲库首次扫描仍是 I/O 密集的（每个文件都要解析元数据），增量重扫很快。
- 均衡器是 10 段固定频点，不是参数均衡。
- 深色画布上的 Canvas 径向渐变有轻微色带，未做抖动。
- 歌曲列表里还没有标出每首歌来自平台还是本地。
- 未登录时在线首页内容偏少。

</details>

<details>
<summary><b>发布新版本</b></summary>

```bash
# 1. 改 package.json 的 version（更新检查拿它和远端 Release 比）
# 2. 打包
npm run dist
# 3. 提交、打 tag、推送
git add -A
git commit -m "release X.Y.Z"
git tag vX.Y.Z
git push && git push origin vX.Y.Z
```

然后在 GitHub 建 Release，把**三个文件**拖进附件区：

```
release/Aurora-X.Y.Z-Setup.exe
release/Aurora-X.Y.Z-Setup.exe.blockmap
release/latest.yml
```

`latest.yml` 不能漏——它是自动安装唯一读的清单。应用内「检查更新」走 GitHub Releases API，是另一条路。

更新检查读取的仓库来自 `package.json` 的 `repository.url`。注意 electron-builder 打包时会剥掉 `build` 字段，运行时代码不能读 `build.publish`——这一点曾导致每个已发布版本的更新检查都失效。

</details>
