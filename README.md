# Aurora

一个 Windows 桌面音乐播放器。播你电脑里的音乐文件，也可以接入网易云在线音源。

界面不带固定配色——进度条、导航高亮、舞台的极光带，颜色都来自当前播放的那张专辑封面。

---

## 用起来是什么样

**打开就在唱。** 把正在播的那一句歌词放大放在画面正中，上下几行歌词按距离排开、逐渐变淡。背后是随音乐起伏的极光带和粒子。你想看歌词的时候不需要点开任何面板。

**封面决定颜色。** 播放一首歌，整个窗口的色调会跟着封面走。没有播放时界面是灰的，不抢眼。

**左侧导航，底部播放栏。** 和多数播放器一样的位置，不用重新学。专辑墙、歌曲列表、艺术家、文件夹、播放列表、搜索，都在左边。

## 怎么开始用

### 直接下载（推荐）

去 [Releases](https://github.com/LN334/aurora/releases) 下载最新的 `Aurora-<版本>-Setup.exe` 安装。

安装时 Windows 会拦一次——这个安装包没有购买代码签名证书。点「更多信息」→「仍要运行」就能继续，这不是程序有问题，所有未签名的软件都这样。

### 第一次打开

程序会自己去找你电脑里的音乐文件夹（一般在你用户目录下的「音乐」里）。找到了就会开始扫描，歌曲会出现在左侧「本地音乐 → 歌曲」里。

如果没找到或者找错了位置：左侧「音源」→「添加文件夹」，选你的音乐目录。加入之后只要文件夹里的文件有变化才会重新读取，所以之后再扫很快。

**不想让它自己找？** 左侧「音源」里可以移除它找到的文件夹，然后手动添加你要的那个。移除后它不会再自作主张加回来。

### 想听网易云的歌

左侧「在线音乐 → 搜索在线音乐」，直接搜就能听，不用登录。

登录之后（左侧「在线音乐」里点登录，或用搜索页的登录按钮）会多出你的歌单、每日推荐、云盘和红心。登录的是**你自己的网易云账号**——能听的只有你这个账号本来就有权限听的歌。

登录状态跟着「档案」走：换一个档案就是换一个账号。左侧底部「我」可以管理档案。

## 主要功能

### 曲库

- 扫描文件夹建索引，读标签、内嵌封面、同目录的 `.lrc` 歌词
- 增量重扫：只重读改动过的文件
- 专辑封面墙、歌曲列表、艺术家、文件夹树
- 专辑详情页按唱片原序排列曲目

### 播放

- 十段均衡器，带 5 组预设，双击推子归零
- 淡入淡出与交叉淡化
- ReplayGain 音量标准化（峰值限幅，不会削波）
- 随机播放、列表循环、单曲循环
- 队列面板：按实际播放顺序显示，可点击跳转、可移除
- 想「下一首播放」某首歌：右键它，或用列表右侧的 ⋯ 菜单

### 歌词

- 支持 `.lrc`：多时间戳、`offset` 偏移、逐字标记、GBK 与 UTF-8 自动识别
- 沉浸歌词舞台：极光带与粒子随音乐起伏
- **桌面歌词**：独立的透明置顶窗口，默认鼠标穿透，永远不会挡住你点下面的东西。解锁后可拖动、可调字号
- 在线歌词：本地找不到歌词时可以联网查（默认关闭，开启前会说明会发送什么）

### 搜索

一个搜索页，顶部两个标签切换来源：

- **本机曲库**：边打边出结果
- **网易云音乐**：按回车搜索在线曲库

两边结果在同一个列表里显示，点一下就能播。

### 播放列表

- 新建、重命名、删除
- 拖拽排序，也支持 `Alt+方向键`
- 导入导出 m3u / m3u8（导入时会告诉你有多少条在曲库里找不到）

### 桌面集成

- 系统托盘：关窗口不退出，音乐继续播。真正退出走托盘右键菜单
- 任务栏缩略图按钮：上一首 / 播放暂停 / 下一首
- Windows 媒体控制（音量键旁边那个控制面板）
- 硬件媒体键

### 键盘快捷键

| 按键 | 作用 |
| --- | --- |
| `空格` | 播放 / 暂停 |
| `方向键左右` | 快退 / 快进 5 秒 |
| `Ctrl + 方向键左右` | 上一首 / 下一首 |
| `方向键上下` | 音量增减 |
| `L` | 打开 / 关闭歌词舞台 |
| `E` | 打开 / 关闭均衡器 |
| `Ctrl + K` | 跳到搜索框 |
| `Esc` | 关闭当前打开的面板 |
| `Ctrl + Alt + L` | 显示 / 隐藏桌面歌词 |
| `Ctrl + Alt + K` | 锁定 / 解锁桌面歌词（解锁后才能拖动） |

### 设置

左侧「偏好设置」里可以改：

- **更新**：检查频率（手动 / 每天 / 每周）、自动下载并安装（默认关闭）
- **在线功能**：在线歌词开关、网易云音质档位
- **播放**：交叉淡化时长、均衡器
- **外观**：桌面歌词字号
- **数据与缓存**：查看占用、清空缓存（不会删曲库和设置）

## 关于网易云

**这不是官方接入，也没有得到任何授权。**

网易云没有对个人开发者开放曲库接口，所以这里用的是社区逆向出来的私有接口（[NeteaseCloudMusicApiEnhanced](https://github.com/neteasecloudmusicapienhanced/api-enhanced)）。这意味着：

- **仅供个人学习自用**。这类接口属于未授权访问，也违反服务条款。
- **随时可能失效**。平台一改就可能坏，被风控识别后账号可能有风险。
- **不能绕过付费**。不破解加密音频、不破解会员音质、不解锁付费专辑。能播的只有你账号本来就有权限播的。
- **QQ 音乐不支持**。

权限不够时，界面会告诉你具体原因（没登录 / 需要会员 / 地区限制 / 只有试听片段 / 已下架 / 请求太频繁 / 网络问题），不会笼统说一句「播不了」。

## 你的数据

**默认状态下，Aurora 不联网做任何和音乐相关的事。** 下面几处需要联网，每一处都要你主动开启。

### 你的音乐和曲库

全部在本机。索引存在本地，不上传任何东西。

### 在线歌词（默认关闭）

歌词优先读音频旁边的 `.lrc` 文件——那是你自己的文件，永远优先。

本地没有时，可以去 [lrclib.net](https://lrclib.net) 查（开源、公开 API、不需要账号）。这个开关默认关闭，打开前会明确告诉你会把**歌曲标题和艺术家**发送出去。查到的歌词缓存在本机，第二次播放就不用再查，离线也能看。

### 网易云账号

- **登录凭据加密后只存本机**。用 Windows 自带的加密（DPAPI）保护，明文不落盘、不进日志。别人拿到你电脑上的文件也解不开。
- **每个档案一份凭据**。切换档案就是切换账号，互不影响。
- **退出登录就清掉了**。
- **但该发给网易云的还是会发**：搜索关键词、你播的歌、账号 cookie 最终都会送到网易云的服务器。上面说的是 Aurora 自己怎么存，不是「用了就不联网」。

### 更新检查

读 GitHub 的公开接口，不上报使用数据。可以改成「手动」检查。

## 常见问题

**装的时候被拦了？**
安装包没有代码签名。点「更多信息」→「仍要运行」。

**扫描不到我的音乐？**
左侧「音源」里手动添加文件夹。如果加进去了但没找到歌，界面会**把正在扫描的路径列出来**——这样你能看出是路径选错了，还是那个文件夹里确实没有音乐文件。

**某个格式播不了？**
支持 mp3、flac、m4a、mp4、aac、ogg、oga、opus、wav、wv、ape、aif、aiff、wma。

**歌词不显示？**
优先找同名 `.lrc` 文件。没有的话可以在歌词舞台上点「在线搜索歌词」（需要先在设置里打开在线歌词）。

**点关闭按钮怎么没退出？**
这是刻意设计的——关窗口只是收进托盘，音乐继续播。真正退出走托盘右键菜单里的「退出 Aurora」。

**换了网易云账号，歌单没变？**
在左侧底部「我」里切换档案。每个档案有自己的网易云账号。

## 这个项目的状况

请先了解这些再决定是否使用：

| 事项 | 实际情况 |
| --- | --- |
| 谁写的 | 代码和文档全部由 AI 生成（DeepSeek 驱动的编码助手），没有人工逐行编写 |
| 稳定性 | 不承诺。功能会改、界面会重做、行为可能不向后兼容，也没有维护承诺 |
| 测试程度 | 有 243 个自动化测试，但只覆盖不需要界面的逻辑部分。**软件本身没有在真实的 Windows 窗口里完整跑过一遍**——开发环境限制导致这一点做不到。第一次运行遇到问题请开 issue |
| 安装包 | 没有代码签名，Windows 会拦一次 |
| 网易云 | 第三方逆向接口，仅供个人学习自用，随时可能失效 |

如果需要一个可靠、有人长期维护的播放器，请用成熟项目。

## 开发者看这里

以下内容面向要改代码或自己构建的人。

<details>
<summary><b>从源码运行</b></summary>

需要 Node.js 22 或更新版本。

```bash
npm install
npm run dev          # 开发模式：热更新 + Electron 窗口
npm test             # 跑测试（不需要 Electron）
npm run preview      # 只构建界面，产出单文件 HTML，双击就能看
```

国内网络下 `npm install` 可能卡在 Electron 二进制下载上，在项目根目录建 `.npmrc`：

```ini
registry=https://registry.npmmirror.com
electron_mirror=https://npmmirror.com/mirrors/electron/
```

这个文件有意没有提交进仓库（它会强制所有克隆的人用第三方镜像）。

</details>

<details>
<summary><b>代码结构与约定</b></summary>

```
src/app/          外壳：App、路由、预览开关、侧栏、标题栏、跨功能 hook
src/features/     功能模块：accounts / library / lyrics / netease / player / playlists / settings
src/views/        页面与面板
src/ui/           共享基元：卡片、封面、图标、列表、时间格式化
src/stage/        歌词舞台与可视化
electron/pure/    零 Electron 依赖、可在裸 Node 下测试的纯逻辑
electron/protocols/  三个私有协议
```

依赖方向单向：`views → features → ui`，`electron/pure` 不依赖其它 `electron` 模块（否则无法在测试里加载）。

界面规则：一页只有一个标题（外壳打印）；本地与在线共用同一套卡片；不在页内造侧栏；曲库操作只在曲库页出现；颜色只来自封面（判断配色看 `src/styles/tokens.css`，不看截图）。

完整记录见 [`docs/ui-design.md`](docs/ui-design.md) 与 [`docs/architecture.md`](docs/architecture.md)。

</details>

<details>
<summary><b>性能测量结果</b></summary>

单核百分比。Windows 任务管理器显示的是全机占用，除以逻辑核心数即可。

| 场景 | 单核忙时 | DOM 变更/秒 |
| --- | --- | --- |
| 空白页对照 | 0.72% | 0 |
| **空闲（暂停）** | **0.73%** | **0** |
| 前台播放，无舞台 | 2.05% | 17.5 |
| 前台播放 + 舞台 | 5.74% | 28.6 |
| 窗口隐藏 | 0.16% | 1.7 |

大曲库（5000 首）：55,209 个 DOM 节点、JS 堆 29 MB、滚动帧间隔 p95 17 ms、超过 33 ms 的帧 0 个。**不需要虚拟化。**

主进程启动链 37.9 ms、常驻 1.04 MB。网易云上游包首次加载 1492 ms / 29 MB，但为懒加载，启动不付。

判定规则：同产物连跑抖动约 ±0.3pp，差异小于 0.5pp 不要声称是优化；跨会话数字不可直接比较，口径与对照方法见 [`docs/perf-baseline.md`](docs/perf-baseline.md)。

</details>

<details>
<summary><b>测试覆盖与已知缺陷</b></summary>

243 个用例只覆盖不依赖 Electron 的纯逻辑：LRC 解析、m3u 编解码、队列推进、文件夹树、版本比较、档案隔离、协议路径校验、扫描节流、网易云相关纯函数。

这组测试抓到过两个真缺陷：按文件夹播放会连带播放同前缀兄弟目录（`C:\Music` 匹配到 `C:\Music2`）；把 IPv4 伪装成 IPv6 的 SSRF 绕过。

三个审计脚本（已接入 `npm run check`）：

```bash
node scripts/audit-reachability.mjs   # 从真实入口走 import 图，找无法加载的文件
node scripts/audit-css.mjs            # 找代码与 HTML 都合成不出来的 CSS 类
node scripts/audit-stale-paths.mjs    # 找指向已不存在文件的路径引用
```

第三个是重构后加的：搬文件之后测量脚本里的旧路径会静默失效——工具找不到模块只记一行 FAILED 就继续，数字从报告里消失而没人注意到。它抓到过一次。

</details>

<details>
<summary><b>已知限制</b></summary>

- 软件没有在真实 Electron 窗口里端到端跑过（开发沙箱无法启动 Chromium）。界面用浏览器渲染加无头截图验证，主进程代码通过类型检查并成功打包，但「双击安装、扫码播放」这条完整路径未经实机验证。
- 网易云接入依赖第三方逆向接口，随时可能失效。
- 曲库索引和在线音源是两套数据：网易云的歌不进本地曲库，也不参与档案隔离。
- 档案只隔离播放列表和网易云账号；曲库、播放偏好、均衡器是设备级的。
- 在线歌词只接了 lrclib.net 一个源。
- 大曲库首次扫描仍是 I/O 密集的（每个文件都要解析元数据），增量重扫很快。
- 均衡器是 10 段固定频点，不是参数均衡。
- 深色画布上的 Canvas 径向渐变有轻微色带，未做抖动。
- 本地与在线的歌单已并列在侧栏，但歌曲列表里还没有标出每首歌来自磁盘还是远端。
- 未登录时在线首页内容偏少。

</details>

<details>
<summary><b>发布新版本</b></summary>

```bash
# 1. 改 package.json 的 version（更新检查拿它和远端 Release 比）
# 2. 打包
npm run dist
# 3. 提交、打 tag、推送
git add -A
git commit -m "release X.Y.Z"
git tag vX.Y.Z
git push && git push origin vX.Y.Z
```

然后在 GitHub 建 Release，把**三个文件**拖进附件区：

```
release/Aurora-X.Y.Z-Setup.exe
release/Aurora-X.Y.Z-Setup.exe.blockmap
release/latest.yml
```

`latest.yml` 不能漏——它是自动安装唯一读的清单。应用内「检查更新」走 GitHub Releases API，是另一条路。

更新检查读取的仓库来自 `package.json` 的 `repository.url`。注意 electron-builder 打包时会剥掉 `build` 字段，运行时代码不能读 `build.publish`——这一点曾导致每个已发布版本的更新检查都失效。

</details>
